1. 方案边界：纯仿真能证明什么，不能证明什么

本方案是《AMD 移植实施手册 V3.0》的裁剪分支：所有涉及开发板、AD9363 实物、频谱仪、过空测试的步骤全部移出执行路径，验证手段统一收敛为四级仿真（浮点参考 → 模块位真 → 链路环回 → 协同仿真）加工具链静态报告（综合、时序、功耗）。通信算法的功能正确性、定点化损失、跳频逻辑、抗干扰闭环的逻辑行为，均可在仿真域内达到与板级等价的比特级置信度。

必须诚实面对的部分：仿真模型是"理想化世界"。凡涉及物理层真实行为的结论（射频芯片内部校准、走线信号完整性、真实信道、器件温漂、软件长稳），仿真只能验证"协议/逻辑对不对"，无法验证"物理上通不通"。这些点在第 4 章逐条列明。

2. 步骤总览与板级依赖一览

十一个步骤线性推进，其中 S2（验证基础设施）是本方案相对 V3.0 新增的关键前置：没有板卡，就必须先把"板卡的仿真替身"建出来——AD9363 行为模型、信道模型、干扰注入源、PS 侧 VIP 环境。依赖标记含义：纯仿真闭环 该步结论在仿真域内完整；仿真替代·降级 仿真可覆盖逻辑但置信度降一级；遗留板级闸 该步产出的结论必须经板级复核才生效。

3. 分步骤实现方案（S0–S10）

每张步骤卡含六个固定字段：目标 / 具体操作 / 工具与材料 / 交付物 / 验证方法 / 出口门槛。卡末"板级遗留"栏明确该步哪些结论悬置、对应第 4 章哪个 BV 条目。模块清单与移植策略与 V3.0 §02 矩阵完全一致，此处不重复，只写仿真路线下的执行差异。

S2验证基础设施：板卡的仿真替身10 人日 · 全员（本方案关键前置）
目标
建成四个可复用的仿真基础设施，使后续所有模块不依赖任何硬件即可完成验证。
具体操作
  • AD9363 SPI 行为模型：寄存器数组 + 读写状态机 + 回读校验，支持异常注入（超时、错误回读、复位中断）；寄存器默认值按 ADI 数据手册/参考配置表填写[4]；
  • 信道模型库（testbench 内）：AWGN、载波频偏 CFO、采样率偏差 SFO、可选多径（瑞利/莱斯），参数全部可配置；
  • 干扰注入源：DDS 生成单音/多音/扫频/部分频带干扰，JSR 可标定，供 S7/S8 使用；
  • PS/PL 协同仿真环境：Zynq VIP（Processing System VIP）+ AXI VIP 搭建，能在 xsim 中执行 PS 侧软件对 PL 寄存器的真实读写序列[3]；
  • 自动比对框架：testbench 输出 vs MATLAB 参考逐拍比对、PASS/FAIL 统计、BER 曲线自动生成脚本（此框架本身即技能包素材）。
工具材料
xsim、SystemVerilog、Zynq/AXI VIP、Python 后处理脚本。
交付物
sim/models/（行为模型与信道库）、sim/vip/、比对框架脚本集。
验证方法
行为模型自测（写入-回读一致性）；信道模型输出与 MATLAB 同参数模型统计特性比对（均值/方差/频谱）；VIP 环境跑通最小读写 demo。
出口门槛
四件套全部通过自测并写 README；任意成员 10 分钟内可用模板起一个新模块 testbench。

  • fft_scan：Xilinx FFT LogiCORE（1024 点流水线，免费）+ 加窗 + 多帧累积；IP 自带行为模型直接在 xsim 中验证；与浮点 FFT 逐 bin 比对（峰位误差 ≤1 bin、幅值差 ≤1 dB）；
  • 可选对照：自研 FFT 移植版做资源/精度/开发量对比（报告加分素材）；

  • 黑名单判决（噪底+余量门限）→ 位图 → 帧头版本号同步 → 跳频集剔除，全链路仿真观察"剔除-保持-干扰消失后恢复"全过程。
工具材料
xsim、FFT LogiCORE、S2 干扰注入源。
交付物
感知闭环 RTL、注入干扰验证报告、四配置对照的仿真域数据（供 S8 成图）。
验证方法
干扰注入后 N 帧内黑名单生效且链路 BER 回落至基线；更新率 ≥10 次/s。
出口门槛
四类干扰场景闭环仿真全过；创新点 2（单芯片感知-决策-跳频闭环）有端到端仿真录像/波形证据。
板级遗留：BV-06（降级）——注入干扰是"已知参数的合规干扰"，真实电磁环境中的干扰形态（非平稳、脉冲式、邻道泄漏）与标定手段（干扰机+频谱仪三方核对）无法仿真。补做入口：V3.0 P5′-S4，需第三块板/信号源与频谱仪档期。

4. 需要板级验证的地方（BV-01 – BV-10）

这是本方案的核心约束清单。每一项给出四栏信息：为什么仿真不够（物理原因）、本方案中的仿真替代（能做到什么程度）、可信度上限（剩余风险是什么）、最小补做入口（将来有板卡时，接到哪一步、需要什么设备、预计工时）。凡标注"影响竞赛指标"的条目，直接对应 V3.0 中 T1–T10 的实测列。

最大单点风险：BV-01 + BV-02

若最终要形成可工作的真实系统，AD9363 真机初始化（BV-01）与排针信号完整性（BV-02）是仅有的两个"仿真完全无法背书、且失败会阻断全链路"的点。好消息是两者的补做成本最低（合计约 2 天），且可以在板卡到货后第一时间独立完成，不依赖其余模块进度。

5. 纯仿真路线的交付物与评审影响

能完整交付的部分

  • 完整工程源码（14+2 模块）+ 一键 Tcl 重建脚本 + 开源仓库（英文目录、MIT/Apache-2.0）；
  • 仿真验证证据链：模块位真比对报告 ×10、异常注入覆盖报告、相位连续性断言报告、捕获性能曲线、仿真域 BER-JSR 曲线族（四配置 × 三档 JSR）；
  • 综合与实现报告：时序收敛证据、资源占用表、功耗估算（标注假设）；
  • IP vs 自研对比实验数据（FIR/FFT 两组），支撑"性能与资源优化"章节；
  • AMD 赛道特有的 15 分材料：LLM 协作记录（日归档）+ skill/ 技能包（golden-ref-compare、gowin2amd-porting、vivado-timing-triage、ad936x-reg-check 等，仿真路线下反而更聚焦、更通用）；
  • 设计报告：全部指标标注"仿真域"，诚实声明验证边界。

无法交付或降级的部分

结论

纯仿真路线能保住 100 分中的约 50 分基本盘（优化 20 + 协作 15 + 文档 15）与部分创新分，但"功能正确性 20 分"与实测演示的缺失使它不适合作为竞赛评奖的最终形态。它的正确定位是：板卡到货前的全速推进方案，或后续补做板级验证的完整前置——因为本方案交付的仿真基础设施（行为模型、信道库、比对框架）在补做板级时一个都不会浪费。

6. 执行建议

  • 关键路径优先：S1 → S2 → S5 → S8 是主线，S2 的验证基础设施宁可多投 2 天也要一次建好，它决定后续所有步骤的验证质量；
  • 证据纪律：报告中每个指标必须携带"仿真域/实测"标签；仿真结论不许出现"达到""实测"等字样，这是纯仿真路线被评审信任的前提；
  • 最小补救策略：若赛程中段能借到任意一块 Zynq 板 + 一个 AD9363 模块（甚至一块 ADALM-PLUTO），优先补 BV-01 + BV-02（约 2 天），它们能以最小成本把"射频配置"从悬置结论变成实测结论，对报告说服力的提升性价比最高；
  • 与主手册的关系：本方案 S0–S10 全部产出（RTL、testbench、报告章节、技能包）与 V3.0 的 P0′–P6′ 完全同构，板卡到位后可无缝并入主手册流程，无返工风险；
  • 每周节奏不变：周一计划、周三自检、周五评审；评审时多过一道固定议程——表 3 的 BV 清单有无条目可降级（如借到设备）。
