# 帧格式规格书 (Frame Format Specification)

> **版本**: v1.0
> **适用模块**: S4 发射链 `frame_tx`（下游 `conv_enc` / `blk_inter` / `qpsk_map` / `srrc_duc` 的帧边界依据）
> **机器可读来源**: `sim/golden_ref/config.py` 的 `FRAME_*` 常量
> **权威实现**: `sim/golden_ref/float_chain/framing.py`（帧层唯一裁判）

## 0. 冻结状态

> **状态**: **已冻结**
> **冻结日期**: 2026-09-28
> **冻结依据**: S4 任务卡「frame_tx：Gold 同步字 + 帧头 + 256B + CRC16」
> **签核证据**:
>   - `python sim/golden_ref/sim/check_framing.py` → `[FRAME-GOLDEN] checks=36 failed=0 status=PASS`
>   - `python sim/golden_ref/gen_frame_sync.py --check` → `[FRAME-SYNC] OK: src/frame_tx_sync.vh 与黄金模型一致`
> **变更策略**: 冻结后任何字段长度、同步字相位、CRC 参数的变更必须走 §9 流程并重跑
> `sim/golden_ref/sim/check_framing.py` 与全部 S4 位真向量（帧一变，五模块向量全废）

**S4 之前工程没有帧层**：`sim/golden_ref` 只有编码/交织/调制/SRRC，定点规格书只冻结位宽。
任务卡要求"五个模块的 RTL 输出与 S1 定点参考逐拍一致"，而 `frame_tx` 参考模型不存在，
位真比对就没有裁判。本规格书补的就是这个缺口——先冻结格式，再冻结裁判，最后才动 RTL。

## 1. 帧结构总览

一帧共 **2160 bit = 270 byte**，字段顺序即发射顺序（MSB-first 串行）：

| 字段 | 比特区间 | 长度 | 说明 |
|---|---|---|---|
| 同步字 SYNC | `[0, 64)` | 64 bit | Gold 序列，接收端相关检测用前导；**不参与 CRC** |
| 帧头 HEADER | `[64, 96)` | 32 bit | 版本 / 保留 / 帧号 / 载荷字节数 |
| 载荷 PAYLOAD | `[96, 2144)` | 2048 bit | 256 byte 净荷 |
| CRC16 | `[2144, 2160)` | 16 bit | CRC-16/CCITT-FALSE，覆盖 HEADER + PAYLOAD |

区间定义由 `framing.frame_offsets()` 提供，TB 与报告一律引用它，不在各处重算偏移。

## 2. 同步字

### 2.1 m 序列优选对（数值验证，非引用）

6 级本原多项式在 GF(2) 上共 6 个，两两共 15 对，其中**优选对**（周期交叉相关集恰为三值）
有 6 对。遍历所得的交叉相关集如下（判据 n 为偶数时为 {−1, −1±2^(n/2+1)} = {−17, −1, 15}）：

| 优选对（多项式掩码） | 交叉相关集 | 备注 |
|---|---|---|
| `0b1000011` & `0b1011011` | {−17, −1, 15} | **冻结选择** = x⁶+x+1 与 x⁶+x⁴+x³+x+1 |
| `0b1000011` & `0b1100111` | {−17, −1, 15} | 备选 |
| `0b1011011` & `0b1110011` | {−17, −1, 15} | 备选 |
| `0b1100001` & `0b1101101` | {−17, −1, 15} | 备选 |
| `0b1100001` & `0b1110011` | {−17, −1, 15} | 备选 |
| `0b1100111` & `0b1101101` | {−17, −1, 15} | 备选 |

另 9 对不满足三值性——这条对照用例留在自检里，用来证明"三值判据"不是恒真条件。

序列生成约定：Fibonacci LFSR，初态 `6'b000001`，每拍输出寄存器 LSB，反馈位进最高位。

| 序列 | 多项式掩码 | 一个周期（63 bit）的十六进制 |
|---|---|---|
| A | `0o103` = `0b1000011` | `410C53D1C96ECD5F`（高位左填充至 64 bit） |
| B | `0o133` = `0b1011011` | `417E5467BAD36243`（高位左填充至 64 bit） |

### 2.2 相对位移的选择准则

Gold 码有相位自由度：`SYNC = A ⊕ Tᵏ(B)`。**两条序列同态起步（k=0）时异或结果前 8 位塌成全 0**
（两条 m 序列开头是同一条 `1,0,0,0,0,0` 轨迹），对前导检测不利，故 k 不能随手取。

遍历 k = 0…62，按三级准则排序（同分取最小 k）：

1. 最长同值游程最短（直接影响相关峰的锐度）
2. 周期自相关旁瓣 `max|R|` 最小
3. 0/1 计数最平衡

搜索结果前四名：

| k | 最长同值游程 | 旁瓣 max\|R\| | \|ones−32\| |
|---|---|---|---|
| **24** | **4** | **16** | **0** |
| 1 | 4 | 16 | 1 |
| 59 | 4 | 16 | 1 |
| 44 | 4 | 20 | 1 |

**冻结 k = 24**：三项同时最优且唯一。自检里有一条检查专门重跑这个搜索并要求
`argmin == 24`——规格里的数字必须是算出来的，不是抄来的。

### 2.3 同步字常量与特性

```
SYNC(64 bit) = 0x517AE4216E7555CA
bin          = 0101000101111010111001000010000101101110011101010101010111001010
```

| 特性 | 数值 | 判据 |
|---|---|---|
| 长度 | 64 bit | 与任务卡一致 |
| 主峰自相关 R(0) | 64 | — |
| 旁瓣 max\|R\| | 16（位移 1、20、32、44、63） | 主峰的 1/4 |
| 0/1 平衡 | 32 / 32 | 完全平衡 |
| 最长同值游程 | 4 | — |
| 非零位移自相关取值集 | {−16, −12, −8, −4, 0, 4, 8, 12, 16} | 无伪峰，且取值集不含 ±20 |

该 64 bit 常量由 `sim/golden_ref/gen_frame_sync.py` 生成到 `src/frame_tx_sync.vh`
（综合期即 LUT-ROM），RTL 不运行时生成；生成器 `--check` 与 `frame_tx` 位真比对两道闸
都指向同一个黄金模型。

### 2.4 为什么是 64 而不是严格周期

6 级 Gold 序列的周期是 2⁶−1 = **63**，凑不出 64。本规格取「63 位周期 + 首位重复」，
理由是保持任务卡约定的 64 bit 长度。代价已量化：末位重复只让非零位移相关值浮动 ±1
（上表取值集仍全在主峰 1/3 以内），对相关检测无实质影响。若后续评审要求严格周期，
须走 §9 变更流程并把帧长从 2160 改为 2159。

## 3. 帧头

32 bit，MSB-first 串行，编码值 = `0x40000100`（版本 01、帧号 0、载荷 256 byte）：

| 位段 | 宽度 | 默认值 | 含义 |
|---|---:|---|---|
| `[31:30]` | 2 | `01` | 版本号；版本变更意味着帧结构变化 |
| `[29:24]` | 6 | `0` | 保留（联调 / 后续跳频信息），本版恒 0 |
| `[23:16]` | 8 | 帧号 | 0 起递增，8 bit 回绕；联调时用于快速定位丢帧 |
| `[15:0]` | 16 | `256` | 载荷字节数（本版恒 256，为变长帧预留） |

## 4. 载荷

固定 **256 byte = 2048 bit**，逐字节 MSB-first 串行。本版不做扰码/白化；若后续需要，
白化序列必须与 CRC 覆盖范围一并在这份规格里重新定义（否则接收端无法复用同一 CRC 口径）。

## 5. CRC16

| 参数 | 值 |
|---|---|
| 算法 | CRC-16/CCITT-FALSE |
| 多项式 | `0x1021` |
| 初值 | `0xFFFF` |
| 输入/输出反序 | 否 |
| 终值异或 | `0x0000` |
| 覆盖范围 | HEADER + PAYLOAD = 2080 bit = 260 byte（**不含同步字**） |
| 标准向量 | `"123456789"` → `0x29B1`（已自检） |

**两条相互独立实现**（避免"自己验自己"）：

- `crc16_bitwise(bits)`：位串行 LFSR，与 RTL 同构，支持非字节对齐输入；
- `crc16_table(data)`：8-bit 查表，与公开标准向量对齐。

自检要求二者在 64 组随机长度输入上逐值一致，且都命中 `"123456789" → 0x29B1`。
注错负例：CRC 覆盖区单比特注入 32/32 全部检出；同步字注错由 `sync_ok` 检出。

为什么不是任务卡写的"8-bit 查表、每拍一字节"：`frame_tx` 的输出是比特串行流
（1 bit/拍，直接喂 `conv_enc`），CRC 在**发射链路内边发边算**——每发一比特更新一次 LFSR，
发完 2080 bit 时 CRC 恰好算完，零额外节拍。设计 RTL 时若改用字节查表，就必须在
2080 bit 之外多出 260 拍字节域，或引入一条并行的字节域，反而更重。此偏差在 §8 登记。

## 6. 比特序与打包

1. **比特流 MSB-first**：`bytes_to_bits(b"\x80")[0] == 1`；
2. **多比特字 MSB-first**：帧头的 `[31]` 位先出现；CRC 高字节先发；
3. RTL 侧多路信号按「高位在前」打包，打包规则写进向量 `meta.json` 的 `packing` 字段。

## 7. 与下游链路的算术衔接

帧长一旦冻结，下游长度随之确定（这是"先冻帧格式、再冻接口"的理由）：

| 环节 | 长度 | 说明 |
|---|---|---|
| 帧 | 2160 bit | 本规格 |
| `conv_enc` | 2 × (2160 + 6) = **4332 bit** | 6 bit 归零尾比特，前导 g₁ 后随 g₂ |
| `blk_inter` | 10 × 434 = **4340 bit** | 深度 10；尾部补零 **8 bit**（与 S1 `block_interleave` 的补零行为一致） |
| `qpsk_map` | 2170 符号 = 4340 bit | 每符号 2 bit（偶位 I、奇位 Q） |

## 8. 边界与口径声明

1. **同步字不参与 CRC**：它是接收端已知前导，不对它做完整性保护；同步字自身的正确性由
   `sync_ok`（相关检测）保证。若要求"同步字也被 CRC 覆盖"，须走 §9 变更流程。
2. **全帧（含同步字）进 `conv_enc`**：发射链是五模块线性串联，不存在旁路，故同步字也会被
   编码。接收端可在解码后做相关检测（S5 决定），本规格不做限定。
3. **同步字长度 64 = Gold 周期 63 + 1**：见 §2.4，属有意偏差。
4. **CRC 实现形式**：位串行 LFSR 而非任务卡建议的字节查表，理由见 §5，属有意偏差。
5. **与 S1 冻结基线的关系**：本规格只描述比特级成帧，不改任何位宽/量化/溢出参数，
   因此**不触发**《定点规格书》§5 的变更流程（`config.py` 中 `FRAME_*` 与
   `FIXED_POINT_CONFIG` 相互独立）。
6. **不在本规格范围内的**：SRRC 抽头数（沿用 S1 冻结的 33 抽头）、NCO 频率字与相位连续语义、
   各模块 valid 握手细节——见 `docs/spec/s4_tx_interface.md`。

## 9. 变更流程

1. 提交变更申请：说明要改的字段、原因、对下游长度与全部 S4 向量的影响面；
2. 修改 `config.py` 的 `FRAME_*` 后重跑 `sim/golden_ref/sim/check_framing.py`（须 `failed=0`）；
3. 重跑 `sim/golden_ref/gen_frame_sync.py` 并 `--check`，确认 `src/frame_tx_sync.vh` 同步；
4. 重新导出全部 S4 向量（`sim/framework/export_vectors.py`）并重跑 `sim/run_s4_acceptance.ps1`；
5. 评审通过后更新本文档版本号与冻结日期。
