千兆以太网原型（eth_mac v0.1）实现说明

从 PHY 环回到 PC 直连 ping/iperf 打通的最小可用千兆 MAC 方案，含模块划分、RGMII 时序要点、关键代码骨架与时序约束。

步骤编号 P1-S4 Day 5–8 · 队员 C 器件 GW5AT-LV60（Tang Mega 60K） 验收 ping 通 / iperf ≥100Mbps

1. 定位与验收目标

这是项目里第一块与外界交互的硬件 IP，价值有三：验证 RGMII 125MHz DDR 接口时序能否在 GW5AT-LV60 上收敛；打通「PC ↔ FPGA」双向数据通道，为 P3 定频链路的 Python 上位机铺路；沉淀一份 125MHz 时钟域的约束写法供 P3 复用。

验收只认两件事：ping 通 + iperf ≥100Mbps。所以不要写 TCP、不要做完整 IP 分片，只做最小子集。

范围红线：v0.1 只做 RGMII + MAC 帧引擎 + ARP/ICMP/UDP 回显。TCP、IP 分片、DHCP、多播一律不在本步骤，避免战线失控。

2. 前置依赖（P1-S3 必须已完成）

eth_mac 的引脚完全依赖 doc/pins.md，开工前先确认：

  • 板上 PHY 芯片型号（以原理图为准，常见 RTL8211 / YT8531 / 88E1512 一类）——RGMII 的 2ns 延迟怎么补，取决于具体芯片，这点先定。
  • RGMII 引脚组：TXC / TXD[3:0] / TX_CTL、RXC / RXD[3:0] / RX_CTL、MDIO / MDC、PHY 复位与中断。
  • 125MHz 时钟来源：板载晶振进 PLL 分频，还是 PHY 输出的 REF_CLK——决定约束怎么写。

3. RGMII 接口要点：125MHz、DDR、2ns 偏斜

这是整步最容易翻车的地方，先吃透三件事：

  • DDR：数据在时钟的上升沿和下降沿都采样/驱动，4 bit 数据线等效 8 bit @125MHz = 1000Mbps。
  • TX 方向（FPGA→PHY）：TXC 与 TXD/TX_CTL 之间要求约 2ns 偏斜（TXC 滞后数据 90°）。FPGA 侧用 ODDR 打数据，TXC 用 90° 相移时钟经 ODDR 恒翻转输出。
  • RX 方向（PHY→FPGA）：PHY 发出 RXC 与 RXD 对齐，但线上有偏斜，FPGA 用 IDDR 在 RXC 双边沿采样。通常让 PHY 开内部 RX delay（约 2ns），FPGA 直接在 RXC 边沿采样即可，最省事。

所以第一步是 mdio_ctrl：把 PHY 的 RGMII delay 寄存器配好 + 千兆全双工自协商，否则后面全是时序幻觉问题。先读 PHY 状态寄存器确认 link 与速率，再查数据通路。

4. 模块划分与数据通路

4.1 rgmii_if —— RGMII ↔ 内部 8bit GMII 桥

用高云原语 IDDR/ODDR 把 DDR 4bit 转成单沿 8bit，内部变成标准 GMII 语义，后续 mac_core 不再关心 DDR。

// ===== RX：RGMII 4bit DDR -> 8bit GMII =====
wire [3:0] rxd_rise, rxd_fall;
wire       rxdv_rise, rxdv_fall;
genvar i;
generate
  for (i = 0; i < 4; i = i + 1) begin : gen_rxd
    IDDR #(.Q0_INIT(1'b0), .Q1_INIT(1'b0)) u_iddr (
      .Q0  (rxd_rise[i]),   // RXC 上升沿采样 = 低 4bit
      .Q1  (rxd_fall[i]),   // RXC 下降沿采样 = 高 4bit
      .D   (rxd[i]),
      .CLK (rxc),
      .RST (~rst_n)
    );
  end
endgenerate
IDDR u_iddr_dv (.Q0(rxdv_rise), .Q1(rxdv_fall), .D(rx_ctl), .CLK(rxc), .RST(~rst_n));

// 内部 8bit：{下降沿, 上升沿}
wire [7:0] rx_data = {rxd_fall, rxd_rise};
wire       rx_dv   = rxdv_rise;

// ===== TX：8bit GMII -> RGMII 4bit DDR =====
generate
  for (i = 0; i < 4; i = i + 1) begin : gen_txd
    ODDR #(.INIT(1'b0), .TXCLK_POL(1'b0)) u_oddr (
      .Q0  (txd[i]),
      .Q1  (),
      .D0  (tx_data[i]),     // 上升沿 = 低 4bit
      .D1  (tx_data[i+4]),   // 下降沿 = 高 4bit
      .CLK (clk_125m),
      .TX  (clk_125m)
    );
  end
endgenerate
ODDR u_oddr_ctl (.Q0(tx_ctl), .Q1(), .D0(tx_en), .D1(tx_en), .CLK(clk_125m), .TX(clk_125m));

// TXC 时钟输出：用 90° 相移时钟让 ODDR 恒翻转（D0=0, D1=1）
ODDR u_oddr_txc (.Q0(txc), .Q1(), .D0(1'b0), .D1(1'b1), .CLK(clk_125m_90), .TX(clk_125m_90));

注意：高云 IDDR 端口为 Q0/Q1/D/CLK/RST，ODDR 端口为 Q0/Q1/D0/D1/CLK/TX（TX 为第二沿时钟）。端口名以所选 EDA 版本的《GOWIN FPGA 原语手册》为准。

4.2 mac_core —— 帧引擎 + CRC32

  • 发送：自动加 7×0x55 前导码 + 0xD5 SFD，握手 tx_data/tx_valid/tx_ready，末尾追加 4 字节 FCS；帧间间隔 IFG ≥ 12 字节（96 bit）。
  • 接收：剥前导码/SFD，校验目的 MAC（本机或广播），末尾 CRC32 校验，crc_bad 时丢帧。
  • CRC32：以太网多项式 0xEDB88320（反射式），32bit LFSR，收发各一份。
module crc32_eth (
    input  wire        clk,
    input  wire        rst_n,
    input  wire        crc_en,      // 当前字节参与 CRC 计算
    input  wire        crc_clr,     // 新帧开始时复位
    input  wire [7:0]  data,
    output wire [31:0] crc           // 发送时需按位取反再反转字节序填入 FCS
);
    reg [31:0] crc_reg;
    integer j;
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)          crc_reg <= 32'hFFFFFFFF;
        else if (crc_clr)    crc_reg <= 32'hFFFFFFFF;
        else if (crc_en)     crc_reg <= next_crc(crc_reg, data);
    end

    function [31:0] next_crc;
        input [31:0] c;
        input [7:0]  d;
        reg   [31:0] t;
        integer k;
        begin
            t = c ^ {24'h00, d};
            for (k = 0; k < 8; k = k + 1) begin
                if (t[0]) t = (t >> 1) ^ 32'hEDB88320;
                else      t =  t >> 1;
            end
            next_crc = t;
        end
    endfunction

    assign crc = crc_reg;
endmodule

4.3 eth_proto —— 最小三层协议栈

  • ARP：收到 who-has → 回 is-at；收到 is-at → 缓存对端 MAC。
  • ICMP echo：收到 echo request → 原样回 echo reply（校验和、ID、序列号回填），这是 ping 通的关键。
  • UDP 回显：iperf -u（UDP 模式）收一个包把 payload 原样发回，用于吞吐验证。TCP 留到 P3 需要时再说。

FIFO 接口按「帧」抽象：rx_frame 是完整以太网 payload，tx_frame 输出。这一层是纯同步逻辑，最容易先用仿真 + Python 参考实现比对。

4.4 fifo_cdc —— 跨时钟缓冲（为 P3 预留）

v0.1 里 PC↔回显全在 125MHz 域，fifo_cdc 先用旁路（同频直连）。但接口现在就按异步 FIFO 设计好：用户侧留可换时钟端口，P3 接入 61.44MHz 基带域时只把旁路换成真 FIFO + 格雷码指针同步，上层一行不改。这正是步骤卡「供 P3 复用」的落点。

5. 实现顺序（对应步骤卡）

  1. mdio_ctrl + PHY 配置：PHY 复位、开 RGMII delay、开千兆全双工自协商，读回 PHY ID/状态确认 link up。
  2. rgmii_if + PHY 环回：自发自收固定测试帧，逻辑分析仪或回环比对，确认 DDR 采样时序正确（步骤卡「先做 PHY 环回」）。
  3. mac_core + CRC32：仿真喂以太网帧，验前导码/CRC 收发正确。
  4. eth_proto（ARP/ICMP/UDP）：仿真用 Python 参考比对，再上板 ping 通。
  5. PC 直连 + iperf：iperf -u 测吞吐，目标 ≥100Mbps；全程 Wireshark 抓包核对。

6. 时序约束（125MHz 域，重点沉淀）

# 125MHz 以太网时钟域（RGMII）
create_clock -name eth_125m -period 8.000 [get_ports {eth_rxc}]
# TX 时钟由 PLL 输出 125MHz（0°）与 90° 相移（给 TXC）
create_clock -name eth_125m_pll -period 8.000 [get_pins {pll_inst/CLKOUT0}]
create_generated_clock -name eth_125m_90 -source [get_pins {pll_inst/CLKOUT0}] \
                       -divide_by 1 [get_pins {pll_inst/CLKOUT1}]
# RGMII 输入时序（相对 RXC 的 skew，参考 PHY 数据手册 tSkewR）
set_input_delay -clock eth_125m -min 0.0 [get_ports {eth_rxd[*] eth_rx_ctl}]
set_input_delay -clock eth_125m -max 2.0 [get_ports {eth_rxd[*] eth_rx_ctl}]
# 异步时钟域（P3 接入 61.44MHz 基带后）
set_clock_groups -asynchronous \
  -group [get_clocks {eth_125m eth_125m_pll eth_125m_90}] \
  -group [get_clocks {baseband_61m44}]

交接：这份写法要交给队员 B，合并进 P1-S7 的 template.sdc（设计报告 §3.8 的四时钟域：125M 以太 / 61.44M 基带 / AD9363 输出时钟 / 20M SPI）。

7. 常见坑与规避

现象根因规避
ping 时通时不通、吞吐上不去忘配 PHY RGMII delay，双沿采样错位先读 PHY 状态确认 link/速率，再查数据
发送方向建立/保持违例TXC 没做 90° 相移PLL 输出锁相与相位选择核对
帧全被对端丢CRC32 用错多项式（非反射 0xEDB88320）与 Python binascii.crc32 比对
千兆下丢帧IFG 太短（<12B）帧间隔 ≥ 96 bit
回显逻辑被淹没没做目的 MAC 过滤只收本机/广播，其余丢
ping 通但 iperf 慢每帧中断式处理，开销大收发流水化、FIFO 深度给足

8. 小结

按 「PHY 配置 → RGMII 接口环回 → CRC32 帧引擎 → ARP/ICMP/UDP → PC 直连压测」五步推进，每步都有独立仿真/抓包验收点。RGMII 的 2ns 偏斜交给 PHY 内部 delay + TXC 90° 相移解决，fifo_cdc 接口从第一天就按异步 FIFO 预留。这样 eth_mac 在 P1 就完成「千兆通路 + 跨时钟骨架」的双重使命，P3 只需把它从 UDP 回显换成接 frame_tx/frame_rx。
