IP vs 手写对比实验报告
33-tap SRRC：FIR Compiler 版 × DSP48E1 手写多相版

对 srrc_duc（手写多相 SRRC）与 srrc_duc_fir（FIR Compiler IP 版）做三栏对比（资源 / Fmax / SFDR）。资源与 Fmax 来自 Vivado 2021.2 布局布线实测；输出误差与 SFDR 由 P3 位真一致结论给出（两版逐拍 0 误差 → SFDR 相同）。

器件 xc7z020clg400-2（-2 档） 目标时钟 61.44 MHz（period 16.276 ns） OOC 模式 + Explore 指令，已路由 系数 12-bit 同源 srrc_fir.coe / srrc_coeff.vh

1. 实验方法（取数口径）

  1. 两版分别以各自原顶层作 top（srrc_duc / srrc_duc_fir），Vivado batch + out_of_context 模式综合与布局布线，端口不插 IOB，聚焦内部寄存器→寄存器的模块级 Fmax。
  2. 统一约束：create_clock -period 16.276 clk；综合/实现固定 Explore 指令，保证两版可比。
  3. 资源取 report_utilization -hierarchical（Routed）；时序取 report_timing_summary -delay_type max，Fmax = 1 / (period − WNS)。
  4. 输出误差 / SFDR 不在本表实测——P3 已证两版与 golden_ref.fixed_point.duc 逐拍位真一致（8712 拍 0 错误），故两版 SFDR 数学上一致。

3. 结论解读

  • DSP「打平」而非手写更省：手写版 66 个 12×12 乘累加里，Vivado 仅把约 14 个映到 DSP48E1（组合路径中 DSP 级联的 PCOUT→PCIN 链路反而拖慢时序），其余落入 LUT；FIR IP 侧为 7 DSP×2=14，加两版共享的 DUC 复数混频 4 DSP，故都停在 18。因此「手写省 DSP」在本例中不成立，差别转移到 LUT/FF 上。
  • Fmax 手写版被 SRRC 组合路径拖死：最差路径为 out_phase_reg → 6 级 DSP48E1 级联(MAC) → 加法树 → round-half-to-even 量化 → DUC 混频(2 DSP) → 量化 → 输出寄存器，全部一拍完成，到达 30.34 ns → 33.8 MHz。FIR 版因 IP 内部三级流水吸收了成形段，只剩 DUC/量化段 → 59.1 MHz。
  • 两版都未达到 61.44 MHz，且瓶颈不在滤波器：FIR 版最差路径源是 phase_acc_reg（NCO 相位累加器）→ dout_data_reg，即「16K×16 NCO 分布式 ROM 的组合查表 + DUC 复数混频 + 量化」这段——它两版共享、且没有流水寄存器。结论是：要整链收敛到 61.44 MHz，需在 NCO→混频路径补一级流水（P5 整链收口事项），而非仅调 SRRC。
  • 资源被共享 NCO LUT 主导：16K×16 的 NCO 四分之一波 LUT 以分布式 ROM 实现（约 4096 LUT6，两版一致，可从 FIR 版顶层 wrapper 的 4783 LUT 反推），占 LUT 总量约 75%。后续若要压面积，把 NCO LUT 改 BRAM 同步 ROM 是比调 SRRC 更大的杠杆。
  • 选型结论：以 Fmax 与交付稳定性看，FIR IP 版明显优于手写版（59.1 vs 33.8 MHz，代价仅 +733 FF）；手写版若保留，必须给 SRRC 乘累加加流水。二者输出位真一致，SFDR 无差异。
P4 遗留（转入 P5 · 五模块整链收口）

本阶段结论不是「选型即闭环」：两版在 61.44 MHz 下均未收敛（手写 −13.32 ns / FIR −0.64 ns），根因是共享的 NCO/DUC 组合路径无流水。建议 P5 优先处理「NCO LUT 改 BRAM 同步 ROM + 混频前插一级流水」，再复查整链时序与资源。
