D3 · 架构决策：从"0 MCU 纯硬件"到"PS/PL 控制面-数据面分离"

高云开放题强制"FPGA 主体地位、不使用 MCU"，AMD 自主选题赛道不作此限，且明确"鼓励综合考虑软硬件协同，充分发挥器件整体性能"。因此架构做如下重划——所有 µs 级实时路径仍在 PL，PS 只做 ms 级控制与人机交互：

PS 侧（ARM Cortex-A9，控制面）新增/替代

以太网：PS GEM 千兆 MAC 硬核（PYNQ-Z2 网口接 PS MIO）→ 替代原自研 eth_mac，裸机 lwIP 或 PYNQ Linux 直连 PC
运行中改配下发：频率/增益/带宽/跳速档/黑名单，经 AXI4-Lite 写 PL 寄存器
状态字采集转发：BER、RSSI、同步状态、频谱峰值 → PC 上位机 GUI（原 Python GUI 保留）
慢速闭环决策：干扰判定、黑名单版本管理、调制阶数切换仲裁（可 PL 先行、PS 监督）
PYNQ 路线（初级组推荐）：Jupyter 组织测试流程与数据采集，PL 封装为 Overlay

PL 侧（可编程逻辑，数据面 100% 实时）移植主体

发射链：frame_tx → conv_enc → blk_inter → qpsk_map → srrc_duc（NCO）
接收链：ddc_rx → sync_rx（载波/位同步）→ viterbi_dec → 解交织 → 解帧
跳频层：fh_ctrl（LFSR-16）→ nco_hop（相位连续） + 跳同步状态机 + TOD 时基
抗干扰层：fft_scan 干扰感知 + 坏信道位图（实时判决留 PL，保证不断链）
射频接口：spi_master + ad9363_cfg 表驱动状态机（0 软件参与初始化，原创新点保留）
PS ↔ PL 接口：AXI4-Lite（寄存器/状态字）+ AXI-Stream（可选高速数据回传）· PL 四时钟域：基带（晶振→MMCM ~61.44 MHz）/ 控制面（PS FCLK_CLK0 100 MHz）/ 射频采样（AD9363 DATA_CLK=采样率）/ SPI ≤20 MHz 伪域（FCLK 分频）；PS GEM 125 MHz 在 PS/MIO 域，不进 PL xdc
答辩话术转变（重要）：原创新点"0 MCU 纯硬件"改写为——"控制面/数据面分离：全部 µs 级实时信号处理在 PL 内闭环完成，PS 仅承担慢速控制与人机交互；跳频规避链路不依赖任何软件参与，感知-决策-跳频在单芯片内闭环"。射频初始化仍由 PL 硬件状态机完成（不用 PS 配置 AD9363），这条红线不动——它是与"直接用 ADI Linux 驱动"作品的差异点。

每个模块的迁移策略在动工前先查此表。原则：创新点模块坚持自研（nco_hop 相位连续、ad9363_cfg 硬件配置），工程效率模块大胆用 AMD 免费 IP（FFT/FIR/CIC）——取舍逻辑本身就是答辩素材。

fh_ctrl直移1dLFSR-16 纯逻辑；黑名单输入端口不变10⁶ 跳比对一致；16 信道均匀

fft_scan替代/自研双轨2dXilinx FFT LogiCORE 免费可用：1024 点流水线版即插即用；若坚持自研叙事可保留原 RTL 移植（BSRAM→BRAM）。建议：主用 IP，自研版作对比实验写入报告峰位误差 ≤1 bin；幅值差 ≤1 dB
