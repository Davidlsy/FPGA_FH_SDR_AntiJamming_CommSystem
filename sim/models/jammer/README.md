# S2 验证基础设施 · 干扰注入源

计划书 §S2 第三件交付物。S7（FFT 干扰感知 + 黑名单判决）与 S8（抗干扰增益验证）
都需要一个**频率、带宽、功率都可标定**的干扰源；没有它，"抗干扰"就只能靠嘴说。
本库提供四类干扰波形与 JSR 标定，并附带频谱与功率的解析判据自核验。

## 1. 组成

| 文件 | 作用 |
|---|---|
| `jm_dds.sv` | 多音 DDS（含单音）：`count` 个复音，频率 `ftw + k·spacing`，等功率合成后按 `1/√count` 归一，总功率恒为 1 |
| `jm_sweep.sv` | 扫频：二阶相位累加（每拍 `ftw += dfw`），锯齿回卷，斜率/起止频率/周期可配 |
| `jm_partial.sv` | 部分频带：全速率白噪声经长度 D 的滑动平均带限，再搬到中心频率 |
| `jm_top.sv` | 类型选择 + JSR 标定 + 与信号相加；干扰波形单独引出 |
| `tb_jammer_stats.sv` | 七场景核验 TB，导出样本到 `dump/` |
| `check_jammer_stats.py` | 解析判据检查器，出一张 31 项核验表 |
| `run_jammer_check.ps1` / `.bat` | 一键：编译 → 跑七场景 → 核验 |
| `dump/`、`logs/` | 场景样本与运行日志（`*.log`，已被 gitignore，可随时重跑重建） |

> 本源复用 `../channel/ch_pkg.sv` 的定点量化（round-half-even + saturate，与
> `golden_ref.quantizer` 对齐）与高斯原语——两处各写一份迟早会不一致。

## 2. 接口

```systemverilog
jm_top #(.W(14), .FRAC(11), .JS(1.0), .MAXTONES(8)) u_jm (
    .clk, .rst_n,
    .in_valid, .in_i, .in_q,
    .cfg_type,          // 0=关闭 1=单音/多音 2=扫频 3=部分频带
    .cfg_jsr_db_x10,    // JSR 以 0.1 dB 为单位
    .cfg_tone_count, .cfg_tone_ftw, .cfg_tone_spacing,
    .cfg_sweep_ftw0, .cfg_sweep_dfw, .cfg_sweep_period,
    .cfg_pb_div, .cfg_pb_ftw,
    .out_valid, .out_i, .out_q,      // 信号 + 干扰（接收机看到的总波形）
    .jm_valid,  .jm_i,  .jm_q        // 干扰本身，供核验与 S7 频谱感知取用
);
```

`cfg_type = 0` 时逐位透明（只多 2 拍流水线延迟），可作恒等自检。所有频率以
**归一化相位增量**给出：`f/fs = FTW / 2^32`，故带符号 32 位可覆盖整个奈奎斯特区。

## 3. JSR 口径（写报告前必须先看这一节）

```
JSR_dB = 10·log10(P_jam / P_signal)
P_jam  = JS × 10^(JSR_dB/10)
```

- **JSR 按总功率定义**，参考信号功率取参数 `JS`（与 `ch_awgn` 的 `ES` 同口径，
  **不在线估功率**）。换调制方式或成形系数时必须同步改 `JS`，否则名义 JSR 与实际不符。
- **部分频带干扰另有「带内 JSR」**：只有一部分干扰功率落在信号带宽内，对 BER 真正
  起作用的是带内那个比值。本库的 JSR 是**总功率比**，报告里引用时务必写清用的是哪个。
- 干扰功率在**相加之前**测量：`jm_*` 单独引出就是为此。高 JSR 下和信号会顶到
  14/11 的 ±4.0 轨（实测 JSR 10 dB 时 8192 拍里有 512 拍削顶），此时从 `out_*`
  量到的是削顶后的波形，不是干扰真实功率。

## 4. 核验（31 项解析判据，本机全部通过）

```powershell
.\run_jammer_check.ps1        # 或双击 run_jammer_check.bat
```

七个场景顺序跑，每个场景前复位一次（相位累加器/噪声种子/滤波缓冲归零）：

| 场景 | 核验内容 | 实测 |
|---|---|---|
| `off` | 关闭干扰时逐位透明、干扰输出恒 0 | 2048 拍 0 失配 |
| `tone_0/5/10` | 峰频 = FTW/2³²、总功率、纯度、三档 JSR 标定 | 峰频 0.06250000（期望 0.06250000）；杂散 −79.2 dBc；JSR 实测 −0.0002 / 5.0003 / 9.9998 dB |
| `multitone` | 四个峰的频率与功率均衡、总功率仍为 JS | 4 峰、频率误差 0、功率比 1.0002 |
| `sweep` | 瞬时频率斜率 = DFW/2³²、起点 = FTW0/2³²、周期、功率 | 斜率 2.441e-4（期望同）；起点 −0.12500000；周期 1024.0 拍 |
| `partial` | 双边 −3 dB 带宽、带外功率占比（对 sinc² 解析值）、总功率 | 带宽 0.10405 fs vs 0.11073；带外 9.31% vs 解析 9.83% |
| `sum` | 每个场景核对 `out = 量化(信号 + 干扰)` | 最大误差 0.000 码 |

明细表落 `data/s2_jammer_stats/jammer_stats_table.csv`（与 `data/s1_ber_baseline/`、
`data/s2_channel_stats/` 同一证据约定）。检查器输出一行 ASCII 机器可读结果：

```
[JM-RESULT] check=tone5_jsr status=PASS measured=5.0003 dB expected=5.0000 dB tol=0.2 dB
[JAMMER STATS] PASS (31 项全部达预期)
```

## 5. 怎么接到 S7 / S8

- **S8 串联位置**：`TX → ch_top（多径/SFO/CFO，AWGN 先关）→ jm_top → AWGN`。
  干扰是外部入射的确定性波形，热噪声在接收机内，故干扰在前更符合物理次序。
- **S7 频谱感知**：FFT 输入取 `out_*`（接收机实际看到的波形，干扰+信号+噪声）；
  要单独标定感知算法对纯干扰的响应时取 `jm_*`。
- **逐信道干扰（黑名单场景）**：干扰源本身不带跳频调度，按跳频表驱动 `cfg_tone_ftw`
  （或扫频参数）与 `cfg_type` 即可模拟"只干扰当前跳频频点"；黑名单判决属 PL 逻辑，
  不在本库范围。
- **JSR 扫描**：`cfg_jsr_db_x10` 运行时可配，S7 的 JSR 0/5/10 dB 标定直接扫它。

## 6. 已知边界

| 边界 | 说明 | 影响 |
|---|---|---|
| **源输出为 16/13 定点** | 幅值分辨率 1.2e-4，比 14/11 输出台阶低一个量级 | 不额外引入可见误差；核验实测杂散 −79 dBc |
| **部分频带是滑动平均带限** | 形状为 sinc²，裙边缓（−18 dB 处才到 ±0.89/D） | ±2×(−3dB) 带宽外仍有约 10% 功率，这是物理事实不是缺陷；要更陡的带边得换滤波阶数 |
| **不含多普勒/时变功率** | 干扰幅度在场景内恒定 | 快变化干扰需外部调制 `cfg_jsr_db_x10` |
| **不含跳频跟踪逻辑** | 干扰不"跟着跳" | 跳频干扰场景由外部按跳频表驱动频率 |
| **JS 需与调制口径同步** | 不在线估信号功率 | 换调制/成形系数要同步改 `JS`，否则 JSR 名义值失真 |

## 7. 踩过的坑

| 现象 | 原因 | 对策 |
|---|---|---|
| 频谱里多出约 −39 dBc 的假杂散 | 三个波形源的输出都过一级寄存器，而信号直通路径没有，干扰比信号晚一拍，首采样为 0 | 在 `jm_top` 的信号路径补一级寄存对齐 |
| 部分频带带宽测出来偏窄 35% | 用平滑周期图的 `argmax` 当 −3 dB 门限，而噪声 PSD 的峰值是上偏的随机起伏（可达局部均值 1.4 倍） | 参考电平改用峰值附近的**局部均值** |
| 带外功率占比误判为超标 | 拿想当然的 −10 dB 门限卡它，而 sinc² 裙边理论上就有约 10% 落在带外 | 改为与 sinc² 的**解析积分**比，容差按百分点给 |
| 解析预测值差了 2 倍 | 测量区间是 ±2×单边 −3dB 带宽，解析积分上限却只取了 1× | 积分上限取 `2·x3`，与测量区间对齐 |
| 变量被两个进程驱动 | `initial` 与 `always_ff` 同时写 `seed_q` | 种子与抽头生成收进同一进程（同信道库） |
| dump 全空 | 开/关激励拆成两个任务背靠背调用，同一时间步内被置 1 又清 0 | 开关激励放同一任务里隔着时钟沿做（同信道库） |
